# 6. Frontend ขอบเขต และการตัดสินใจ

## Frontend

- React + Vite และ TypeScript ไม่ใช้ Next.js
- React Router ≥ v8 และ MUI ≥ v9 เป็นเงื่อนไขเวอร์ชันที่คงไว้ในโจทย์ฝึก
- ขั้น scaffold ตรวจ npm metadata และติดตั้ง React Router 8.3.1 กับ MUI 9.4.0 แล้ว ทั้งสองส่วนผ่าน typecheck/build ดูผลและข้อจำกัดใน ../AI_WORKFLOW.md การตรวจนี้ยังไม่ใช่หลักฐานว่าฟีเจอร์ทั้งหมดทำงานร่วมกันแล้ว
- เชื่อมต่อ Backend API ของโปรเจกต์และ Auth0 ของตนเอง

| หน้า | พฤติกรรมหลัก |
| --- | --- |
| /collections | รายการของตนเอง ดูรายละเอียด สร้าง และลบ |
| /bookmarks | รายการของตนเอง ดูรายละเอียด สร้าง ลบ และกรองตาม Collection |

มีเส้นทาง /callback สำหรับรับผลล็อกอิน ไม่ถือเป็นหน้าฟีเจอร์ที่สาม

## ประเด็นสำหรับฝึกตัดสินใจ

1. เมื่อลบ Collection จะจัดการ Bookmarks ที่อยู่ภายในอย่างไร?
2. หากอนาคตอยากส่ง Collection ให้ผู้อื่น จะจัดการความต้องการนี้อย่างไรให้สอดคล้องกับความเป็นส่วนตัว?
3. API ควรตอบอย่างไรเมื่อข้อมูลไม่มีอยู่หรือเป็นของผู้ใช้อื่น?
4. การแทนที่ข้อมูลทั้งหมดต่างจากการแก้ไขบางส่วนอย่างไร?

บันทึกทางเลือก เหตุผล และผลกระทบใน DECISIONS.md พร้อม tests รองรับพฤติกรรมที่เลือก การแชร์ไม่ใช่ฟีเจอร์บังคับ และต้องไม่เปิดข้อมูลข้ามผู้ใช้ในขอบเขตแอปนี้

## ฟีเจอร์เสริม

ทำหลังงานหลักและการตรวจสอบมั่นคงแล้วเท่านั้น: Docker, CI/CD, หน้า /all ที่แสดง Bookmarks ภายใน Collections และ full-text search ใน title/notes

ความสัมพันธ์ Collection–Bookmark และ API รายการย่อยเป็นงานหลัก ไม่ใช่ฟีเจอร์เสริม

## กรอบเวลา 1–2 วัน

ช่วงแรกเน้นตั้งค่า spec, Auth0 ของตนเอง, schema และ Backend พร้อม tests ส่วนสำคัญ ช่วงถัดไปเชื่อม Frontend ตรวจ end-to-end ทบทวนโค้ดและจัดเอกสาร

เก็บหลักฐานระหว่างทำงาน หากเวลาไม่พอให้เลื่อนฟีเจอร์เสริม ระบุส่วนที่ยังไม่เสร็จอย่างตรงไปตรงมา
